Bedienungsanleitung

AUTOSAR Classic Multi-ECU-Portfolio — Demo, Evidenz und CI-Gates lokal ausführen · User Guide (local dev + evidence reproduction)

1. Schnellstart

Alle Szenarien sind deterministisch (kein RNG): ein Aufruf produziert immer dasselbe CAN-Trace und dieselbe Evidenz. Für sofortige Ausführung:

make clean build
make run            # Szenario "normal" (ECU1→ECU2, 100 ms Zyklus)
make test           # 27 Unit-Tests (Host-Modell)
make evidence       # 11 Szenario-Logs nach evidence/  erzeugen
make coverage       # 100% Zeilen / 92.45% Zweige — Gate weist Abweichung zurück
make tidy           # clang-tidy, 0 Warnungen gefordert

Nur das Demo ausführen (alias): ./$(BIN) normal mit den Szenario-Namen aus §2.

3. Szenarien (Determinismus-Evidenz)

Eine Szenario-Nummer aktiviert Fehlerinjektion in virtual_can.c. Jede Injektion ist an einen exakten Zeitstempel gebunden → reproduzierbar:

normal
nominal, kein Fehler
timeout
300 ms kein Frame → RX-Timeout
invalid-id
CAN-ID 0x777 injiziert
invalid-dlc
DLC=2 korrumpiert
invalid-range
Speed 250→251 kph (Range)
invalid-seq
Sequenzzähler doppelt
wrap
Zähler-Wrap 255→0→255
uds
UDS 0x22 DID 0x0801
uds-dtc
UDS 0x19 ReadDTCInformation
wdgm-recovery
WdgM FAILED→OK Recovery

3.1 Beispiel-Trace (uds)

[0600ms][BUS] UDS_INJECT id=0x7DF dlc=8 data=02 22 08 01 ...  (ReadDataByIdentifier)
[0600ms][BUS] UDS_RESP  id=0x7E8 dlc=8 data=06 62 08 01 ...      (VehicleSpeedDID)
Erwartung: Fortsetzung des Nominalpfads; ECU2 meldet E_OK. Ungültige Szenarien geben Exit-Code ≠ 0 zurück; das Skript tests/demo_runner.py prüft die Rückgabewerte.

5. Geplante CI (Athrill / Athrill-RH850)

Der CI-Gate läuft zweigleisig: asynchroner PR-Lauf (Host-Modell) plus geplanter Athrill-Lauf (TOPPERS ATK2/Athrill-Docker) über GitHub Actions schedule (z. B. montags 02:00 UTC). Lokale Replikation des geplanten Laufs einschließlich Docker-Image-Bau:

make athrill-scheduled-evidence   # baut/verifiziert Athrill-Image + Regression; 'docker' nötig
Wichtig (Ehrlichkeit) Dieser Repo ist eine Referenz-/Portfolio-Simulation, kein zertifiziertes Produkt: ISO 26262-OSS-Anspruch, Athrill-Ausführung und ASPICE CLA-Erklärung werden nicht fallengelassen, aber auch nicht überschrieben. Evidenz beweist Reproduzierbarkeit, nicht Zertifizierung.
